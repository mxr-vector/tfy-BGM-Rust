## 1. 实现与验收

- [x] 1.1 验证五格式解码、30 分钟加载限制、多次请求的取消和失败跳过。已用五种格式的合成音频验证解码，并覆盖时长已知和未知、恰好 30 分钟、后台请求替换与解码中取消。实际缺失文件、损坏 WAV、有效 WAV 验证了跳过上限为 0、1、2 时的尝试顺序和恢复播放条件。
- [x] 1.2 对齐 80 ms 包络、0–12 秒交叉淡化、解码缓存与自然结束处理。已验证传输包络、rodio 混音输出、硬切及自然结束后淡入，以及同一文件复用和同大小文件替换导致的缓存失效。
- [x] 1.3 实现保音高倍速，覆盖默认档位与配置归一化允许的范围，并记录 CPU 与延迟。合成 443 Hz 双声道验证了默认五档、0.25× 和 4× 的主频、声道幅度关系和输出长度，另覆盖循环中变速和暂停的 80 ms 包络。
- [ ] 1.4 记录两分钟 A/B 循环、切歌听感、暂停恢复、失败上限及无可用曲目的结果。合成双声道已连续跑满两分钟，回绕帧与声道对齐；已用自动化测试验证跳过上限、顺序及随机候选耗尽。待实机验收切歌听感与错误提示。
- [x] 1.5 核对自然结束及路径变化。自然结束后的下一首或重播按配置淡入。同一曲目换路径时，先取消旧请求，再按原位置和播放或暂停状态启用新音源。用 PCM 混音测试验证恢复的位置、循环及传输包络。

对齐依据为作者文档 F05 和 Git 中的 `bgm-tauri2@8ba4f85`。

变速性能记录（arm64，`rustc -O`，48 kHz 双声道合成 PCM，每组生成 60 秒音频，每块 256 帧）。单声部 1.25× 耗时 85 ms，每块处理耗时 P99 为 0.036 ms。双声部 0.75×/1.5× 和 0.25×/4× 各约 127 ms，P99 为 0.046 ms。这里测量 WSOLA 与采样混合的运行时间。倍速切换最多等待一个 20 ms 分段开始匹配，再以约 20 ms 混合相邻分段。设备缓冲延迟和实机听感待验收。
