## Context

契约来自作者文档 §2 的 F15 ASR 模型管理、相关配置表与附录。下载逻辑对照主线 `bgm-tauri2@8ba4f85` 的 `src-tauri/src/models.rs`。

## Decisions

从核实的主线 models.rs 复用目录扫描、下载清单、验证与识别。以本地路径和类型化消息替换 Tauri 路径与事件。16 kHz 带限重采样及低能量分片沿用主线参数。模型目录和上次模型的写入由 F11 的权威操作维护。

模型目录按最多四层子目录扫描，已有的 `lastAsrModel` 保留在共享偏好中。原生设置页使用主线固定九文件清单，合计 987,023,031 字节。ModelScope 仓库入口使用文件 API，独立镜像按本地文件名规则拼接。

macOS 使用系统 curl 流式下载。一个模型目录同一时间只有一个下载任务。临时文件位于目标目录，按响应长度或清单回退长度验收后原子替换。取消时终止传输进程并清理暂存文件，后续任务复用长度符合清单的文件。模型设置提供手动按名称和大小检查、补齐下载和确认后全量重下。全量重下逐个下载到暂存文件，验证响应后替换原文件。组件齐全、推理库是否存在与模型加载状态独立显示。

识别进程通过 sherpa-onnx 2.0.2 C API 加载四件套，同一个子进程复用已加载模型。主进程以 JSON 消息收发状态和识别分段，隔离原生库的初始化或识别失败。GPUI 可从 `TFY_ASR_LIBRARY` 指定的本机绝对路径读取 C API 动态库，也可从应用资源的 `asr/` 目录读取随包库。macOS 打包可通过 `TFY_ASR_RUNTIME_DIR` 同时带上 C API 动态库和同目录依赖，由构建脚本逐个签名。

空闲时定期检查识别子进程。进程退出后清理加载状态，显示错误并允许重新加载同一模型。识别通信或协议失败使会话失效。文件识别错误由仍在运行的子进程返回，会话可继续使用。

加载成功后保存相对模型键，应用启动时在当前目录尝试恢复。显式释放清除恢复偏好。单声道 WAV 归一到 16 kHz，分片边界选取目标时刻附近的低能量位置，识别结果清除模型控制标记。

按 §8.2 用隔离配置和可重复测试素材验证功能与数据。验收记录包含成功、失败和重启行为。
